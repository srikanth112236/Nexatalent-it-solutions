## Component contract

Each component must document:

- purpose
- props
- variants
- responsive behavior
- accessibility behavior
- motion behavior
- data requirements
- empty/error states
- usage examples

## Reusability rule

If the same visual pattern appears on three pages, it becomes a reusable component.

If a component contains business-specific copy, move that copy into page content/configuration rather than hard-coding it into the visual component.
